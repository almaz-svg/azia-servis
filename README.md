# Сынақ

Платформа оценки учебников и учебных часов. Методист загружает Excel с результатами, приложение считает статусы тем, сравнение учебников с поправкой и кривые «цена часа». Все расчёты идут в браузере: данные школ не отправляются на сервер.

**Статус:** готовы К1–К3 (каркас, расчёты, экраны «Данные», «Темы», «Учебники», «Часы»). Не готовы: апробация (участник и проектор), текст обоснования с LLM, деплой. Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), раздел 17.

## Требования

- Node.js 20.9 или новее (проверено на 24.14)
- npm
- Интернет при `npm install`: пакет `xlsx` ставится с `cdn.sheetjs.com` (так задано в `package.json`)
- Для сквозного теста (`npm run e2e`): Microsoft Edge или другой Chromium, см. `BROWSER_CHANNEL` ниже

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Приложение сразу показывает демо-данные, сеть и Supabase для этого не нужны.

## Как пользоваться

Шаги идут по левому меню. Расчёты выполняются в браузере, файл школ никуда не отправляется.

1. **Данные** — загрузите выгрузку `.xlsx` или `.csv` либо откройте демо-данные. Загруженный файл сохраняется в браузере (IndexedDB) и переживает перезагрузку страницы. «Очистить данные» удаляет его. Шаблон для выгрузки — кнопка «Скачать шаблон».
2. **Темы** — карта «тема × школа» и статус каждой темы: «Норма», «Проблема учебника», «Проблема программы» или «Мало данных». Подсказка «почему такой статус» показывает правило и числа, на которых оно основано.
3. **Учебники** — разница учебника Б относительно А без поправки и с поправкой на уровень школ, с 95%-интервалом. Переключатель меняет числа и вывод.
4. **Часы** — кривая «цена часа» по теме. Кнопка «Перераспределить часы» переносит часы между темами: сумма по параллели не меняется, каждая тема остаётся в пределах ±20% от фактических. Ручные кнопки «+» и «−» переносят по 1 часу. Прогноз помечен как оценка модели.
5. **Апробация** — пока не готова (К4).

Язык интерфейса переключается в шапке: RU или KZ. Выбор запоминается.

## Формат входного файла

Принимаются `.xlsx` с листами «Результаты» и «Уроки» и `.csv`. CSV содержит один лист, он считается листом «Результаты». Без листа «Уроки» экран «Часы» не работает, остальные экраны работают.

**Лист «Результаты»:** одна строка — класс × раздел × учебник.

| Колонка | Что писать | Правило |
|---|---|---|
| Учебный год | например `2025-2026` | текст |
| Район | название района | текст |
| Школа | код, например `Т-01` | текст |
| Тип | `город` или `село` | из списка |
| Учебник | `А` или `Б` | из списка |
| Класс | например `5А` | текст |
| Раздел | название темы | текст |
| Учеников | число учеников в классе | целое, 1–1000 |
| СОР % | среднее по классу, % | 0–100, может быть дробным |
| Входной уровень % | средний уровень класса в прошлом году, % | 0–100, нужен для поправки |

**Лист «Уроки»:** одна строка — класс × раздел.

| Колонка | Что писать | Правило |
|---|---|---|
| Учебный год | как в листе «Результаты» | текст |
| Школа | код школы | текст |
| Класс | как в листе «Результаты» | текст |
| Раздел | как в листе «Результаты» | текст |
| Часов по плану | часы из КТП | целое, 0–500 |
| Часов по факту | фактически проведённые уроки по разделу | целое, 0–500 |

Файл с ошибками не принимается целиком. Приложение показывает до 50 ошибок и указывает лист, строку и колонку, например: «Лист «Результаты», строка 14, колонка «СОР %»: «восемь» — не подходит. Ожидается: число от 0 до 100». Отклоняются также:

- файл с колонкой ФИО: персональные данные учеников в выгрузку не входят;
- повторная строка с тем же классом, разделом и учебником;
- файлы других форматов (например, `.pdf`).

## Демо-данные

Демо-данные синтетические и помечены меткой «Демо-данные» на всех экранах. Генератор детерминированный: 20 школ, классы 5А, 5Б, 6А и 6Б, 10 разделов математики, учебники А и Б, по 800 строк на каждый лист. Встроенные закономерности: у учебника Б освоение по «Обыкновенным дробям» ниже примерно на 10 п.п., а по «Процентам» освоение ниже 60% у обоих учебников. Ожидаемые статусы: «Обыкновенные дроби» — «Проблема учебника», «Проценты» — «Проблема программы». Сквозной тест проверяет оба статуса.

### Сквозной тест

```bash
npm run build
npx next start -p 3100        # в отдельном терминале
npm run e2e
```

Переменные окружения для `e2e`:

- `BASE_URL` — адрес приложения, по умолчанию `http://localhost:3100`
- `OUT_DIR` — папка для скриншотов, по умолчанию временная папка системы
- `BROWSER_CHANNEL` — канал браузера, по умолчанию `msedge`. На машине без Edge укажите `chrome`

Сквозной тест проходит по сценарию методиста: загрузка файла, ошибки в файле, демо-статусы, переключение языка, сохранение файла, очистка. Скриншоты сохраняются в `OUT_DIR`.

## Тесты

`npm test` запускает юнит-тесты (Vitest):

- `src/core` — валидация файла, статусы тем, статистика (регрессия с кластерами по школе, распределение Стьюдента, сравнение учебников), кривая «цена часа», оптимизатор часов, границы слоёв;
- `src/workers` — движок расчёта и кэш результатов;
- `src/data` — демо-генератор и чтение и запись Excel;
- `src/i18n` — паритет ключей ru и kk, подстановка чисел;
- `supabase/tests` — функции апробации на `pglite`: права доступа, баланс групп, идемпотентность ответов, скрытие групп меньше 5 ответов.

Перед коммитом запускайте `npm run check`: проверка типов и тесты. Для изменений в интерфейсе запускайте сквозной тест (`npm run e2e`).

## Переменные окружения

Шаблон лежит в `.env.example`. Для демо файл `.env.local` не нужен.

| Переменная | Назначение | Статус |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Адрес проекта Supabase (апробация) | Пока не используется |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ Supabase | Пока не используется |
| `NEXT_PUBLIC_TRIAL_SOURCE` | `live` или `snapshot` (запасной режим апробации) | Пока не используется |
| `LLM_API_KEY` | Ключ LLM. Только на сервере, никогда с префиксом `NEXT_PUBLIC_` | Пока не используется |

Файлы `.env` и `.env*.local` в git не попадают.

## Структура

Кратко. Полное описание — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), раздел 3.

- `src/core` — чистая логика: статистика, статусы, кривые, оптимизатор. Без React, DOM и сети
- `src/workers` — Web Worker: разбор Excel и вызовы `core`
- `src/data` — демо-датасет (фиксированный seed), хранение в IndexedDB
- `src/features` — экраны
- `src/app` — маршруты Next.js
- `src/i18n` — `ru.json` и `kk.json`, ключи должны совпадать
- `supabase/migrations` — схема апробации: таблицы, RLS, RPC-функции
- `tests/e2e` — сквозной тест

Правила границ и словарей проверяют тесты: `src/core/boundaries.test.ts` и `src/i18n/i18n.test.ts`.

## Supabase (нужно для апробации, К4)

Миграция есть (`supabase/migrations/20261110000000_trial.sql`), но файла `supabase/config.toml` пока нет. Перед `supabase start` создайте его командой `supabase init` в корне проекта. Тесты RPC на `pglite` (`supabase/tests`) Docker не требуют.

## Заметки для разработки

- `vitest.config.ts` использует пул `vmThreads`. На Windows с Vitest 5.1.0 пул по умолчанию падает. Не меняйте пул, не проверив тесты.
- Ключи, токены и `.env*.local` не коммитим. Шаблон — в `.env.example`.
- Статус открытых вопросов (состав эталонных ответов апробации, проверка казахских строк, git) — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), раздел 16.
