# Сынақ — что сделано

Дата: 2026-11-10. Основа: [ARCHITECTURE.md](ARCHITECTURE.md), раздел 17. Проверка типов и тестов выполнена 2026-11-10 (см. раздел «Проверка»).

## Коротко

Платформа оценки учебников и учебных часов. Методист загружает Excel, приложение считает статусы тем, сравнение учебников с поправкой и кривые «цена часа». Все расчёты идут в браузере, данные школ на сервер не уходят.

- **Готово:** К1, К2, К3 (каркас, расчёты, экраны «Данные», «Темы», «Учебники», «Часы»). Из К5 — текст обоснования по шаблону и его копирование.
- **Не начато:** К4 (апробация), остаток К5 (LLM, .docx, деплой), финал.

## Что сделано

### К1 — каркас, данные, база

- Next.js 16, React 19, TypeScript (strict), Vitest.
- `src/core`: типы данных, коды ошибок, конфиг методики `ANALYSIS_CONFIG` v1.0.0, валидация листов, `datasetId` (SHA-256).
- `src/data`: демо-генератор на фиксированном seed (20 школ, по 800 строк в листах «Результаты» и «Уроки»), чтение и запись `.xlsx`/`.csv` через SheetJS 0.20.3.
- `supabase/migrations/20261110000000_trial.sql`: таблицы, RLS, функции `create_trial_session`, `join_trial`, `submit_trial`, `trial_stats`, права для `anon`.

### К2 — расчёты и экраны методиста

- Статистика (`src/core/stats`): распределение Стьюдента, взвешенный МНК с кластеризацией по школе, сравнение учебников с поправкой и без неё.
- Статусы тем (`src/core/status.ts`): четыре правила в фиксированном порядке, подсказка «почему такой статус».
- Кривая «цена часа» (`src/core/curve.ts`): перебор τ по сетке, M и β в замкнутой форме, часов до 70%, отдача следующего часа.
- Один объект `Analysis` для всех экранов. Фильтры по классу, учебнику и району сужают выборку до расчёта.
- Web Worker (`src/workers/`) с кэшем на 12 записей.
- i18n: `ru.json` и `kk.json` с одинаковыми ключами, множественные формы через `Intl.PluralRules`.
- Экраны «Данные» (загрузка, демо, шаблон, ошибки, очистка с подтверждением) и «Темы» (карта 10 × 20, фильтры, подсказки).
- Загруженный файл хранится в IndexedDB и переживает перезагрузку страницы.

### К3 — учебники и часы

- Оптимизатор (`src/core/hours.ts`): автоматический режим шагами «донор → получатель», ручной шаг ±1 час, ограничение ±20% от исходных часов.
- Прогноз по 7.8 помечен на экране как «оценка модели».
- Переключатель «с поправкой / без поправки» меняет вывод и интервалы.
- Экран «Учебники»: CompareBar и сводка надёжности.
- Экран «Часы»: график с пунктиром экстраполяции и линией 70%, таблица точек, оптимизатор, кнопка «Вернуть фактические часы».
- Worker: запрос `plan` с режимами `view`, `auto`, `step`.
- `vitest.config.ts` использует пул `vmThreads`. На Windows пул по умолчанию падал.

### После К3 — обоснование и доработки

- **Обоснование (F7, P0):** `src/core/note.ts` собирает факты из готовых `Analysis` и `HourView` и ничего не пересчитывает. `src/features/note` строит текст по шаблону на RU и KZ. Блок «Обоснование» стоит на экране «Часы» под графиком, кнопка «Скопировать обоснование» кладёт текст в буфер обмена. В тексте есть метка «Демо-данные», версия методики и короткий ключ расчёта.
- **Демо-генератор:** отдача часа теперь своя у каждой темы (`HOUR_EFFECT` в `src/data/demo.ts`). Перераспределение на демо делает 14 переносов и даёт прогноз +1,06 п.п.
- **Карта тем:** навигация стрелками, Home и End по ячейкам; подсказка ячейки читается из `aria-label`.
- **Шрифты:** Unbounded и Golos Text подключены через `next/font` и раздаются самим приложением. Интерфейс не зависит от Google Fonts во время показа.
- **Язык:** выбор читается через `useSyncExternalStore`; в приватном режиме держится до закрытия вкладки.
- **Числа:** `formatSigned` берёт знак у округлённого значения, «−0,0» больше не появляется.
- **Инфраструктура:** ESLint (`eslint.config.mjs`, правило границ `src/core`), `.gitattributes` (LF), иконка сайта `src/app/icon.svg`, CI в `.github/workflows/ci.yml` (линтер, типы, тесты, сборка).

## Что не сделано

### К4 — апробация

- Участник: вход по коду сессии, 3 вопроса, офлайн-очередь в localStorage.
- Проектор: QR-код, опрос `trial_stats` раз в 1 с, вердикт.
- Эталонные ответы `trial_keys` должен дать методист. Без них `submit_trial` возвращает `keys_missing`.
- Нет `supabase/config.toml` (создаётся через `supabase init`), нет Supabase-проекта и Docker. Интеграционные тесты RPC на настоящем Supabase не запускались. Функции покрыты тестами на pglite.

### К5 — текст обоснования и деплой

- Маршрут `/api/note` не создан. LLM не подключён, работает только шаблон текста. Проверки `validateNote` (числа текста LLM против фактов) тоже нет: она нужна только вместе с LLM.
- Экспорт .docx с таблицей «было → стало» (P1). Копирование текста готово.
- Полный KZ/RU: казахские строки не проверены носителем языка.
- Деплой на Vercel и отдельный Supabase-проект для демо.

### Финал

- Три прогона сквозного пути, запасной режим `snapshot`, видео, питч.

### Инфраструктура

- Prettier не подключён.
- В ветке `main` один коммит (К1–К3). Работа после К3 лежит в ветке `note-and-ci` и ждёт слияния в `main`.
- Результат первого запуска CI на GitHub не проверен.

## Ограничения демо

- Оптимизатор на демо делает 14 переносов: часы уходят из «Натуральных чисел», «Отношений и пропорций» и ещё двух тем в «Проценты», «Обыкновенные дроби» и «Рациональные числа». Пример ТЗ «на 6 часов больше» буквально не воспроизводится.
- Кривая для учебника Б по дробям строится с экстраполяцией: часов до 70% больше, чем наблюдалось.
- Прогноз по 7.8 усредняет по темам. На демо он даёт +1,06 п.п.
- Приёмка на демо: «Обыкновенные дроби» — «Проблема учебника» (Б на −10,4 п.п., интервал [−11,8; −9,0]); «Проценты» — «Проблема программы» (53% и 52%).
